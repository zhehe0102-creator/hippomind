01 / Why · 缘起

要解决的不是「存得下」，而是「信得过」

2026-08-15 的调研横向比较了 38 个记忆相关项目（Letta / MemGPT、Mem0、Graphiti、HippoRAG、MemOS、MIRIX、LongMemEval……）。结论是：记忆系统最重要的不是存了多少，也不是有多少种打分，而是一套可审计的记忆生命周期。

BEFORE / 没有 HippoMind

每个 Agent 各自失忆

  • 跨会话经验清零，一次踩过的坑下次还要再踩
  • 「让 AI 记一下」= 塞进系统提示词，越堆越长
  • 聊天记录散落各处，无法检索、无法对账
  • AI 说错了没人纠正，旧事实和新事实混在一起
AFTER / 有了 HippoMind

共享一份会自我修正的记忆

  • 一次学到的部署参数 / 踩坑教训，所有 Agent 可检索
  • 按当前任务动态组装最小 Context Pack（≤8 条、带证据）
  • 自动采集 → SQLite/WAL 单文件账本，FTS + LIKE 双通道
  • feedback 升降权 + claim 冲突检测 + 人工裁决
PRINCIPLE 01

形成质量

什么值得写。事实、经历、技能、临时状态不能混为一类；每条记忆要有来源、时间、有效期和替代关系，新事实不应把旧证据直接删掉。

PRINCIPLE 02

信用分配

「被召回」不等于「帮助了行动」。召回只做小幅饱和升权，真正的强化必须来自环境、用户或评测器的外部反馈。

PRINCIPLE 03

精准召回与弃权

检索同时看语义、关键词、时间、图关系与可用性；证据不足时必须允许「不知道」，空结果给出过滤原因而不是无关填充。

PRINCIPLE 04

容量预算与归档

活跃区有硬上限（默认 180 / 96 / 600）。遗忘首先是退到冷归档，而不是一步永久删除；任何记忆都能追溯到来源。

PRINCIPLE 05

可观测与评测

必须能回答「为什么召回这条」「哪条记忆导致错误」，并用长期更新、时间推理、弃权和真实任务收益验收。

BOUNDARY

驱力的边界

融合「心潮·念」动态驱力引擎，形成欲望影响记忆、记忆影响行动的闭环；但驱力只影响注意力与探索顺序，不能改变事实真伪、证据来源或跳过外部反馈。

最终验收不是「记忆越来越多」，而是：在固定存储、检索和 token 预算下，Agent 的任务收益持续提高，知识更新不返回过期答案，证据不足时会弃权，且任何记忆都能追溯到来源。

02 / Architecture · 系统架构

四层数据流，一本事件账本

HippoMind 是本机单用户记忆中枢，不是云数据库、不是远程授权服务、也不是指令源。持久事实是 SQLite/WAL 事件账本；Context Pack 只是从账本派生、给单次请求使用的有界非可信视图。

STORAGE MODEL / 事件溯源

写入先落事件，投影随时可重建

每次写入先落 ledger_events（不可变审计流），memories 表只承载权重、触碰、效用、归档、替代和过期等可恢复投影 —— 改错可回滚，历史不可篡改。整个记忆就是一个 .sqlite 文件（+wal/shm），备份即复制文件。

Claim 用 (subject, predicate, slot_key) 将过期事实标记为 inactive；relation 保留因果父节点直到整条活跃链可一并归档；结构化事实同时带 valid time 与 asserted time（双时态）。程序性记忆只保存触发条件、前置条件、有序步骤和验证断言，绝不执行存储的命令。

SCHEMA v8 · WAL · FTS5 trigram · 单文件部署
RETRIEVAL CONTRACT / 检索契约

有界、带证据、宁缺毋滥

检索先按 scope / task / project / source / time / lifecycle / evidence 过滤，再融合关键词与 FTS5 信号、新鲜度、重要性、效用、置信度和触碰次数。保留最新高置信结构化状态，分组重叠任务记录，最后用 MMR 为不同历史预留空间。

空结果返回 debug 原因与证据来源，而不是无关填充。非可信内容用动态 nonce 与 XML 实体转义包裹，明确标注为参考数据。

≤8 items · 6000 token · 16000 chars · raw_chat = false
Memory Layers / 五类记忆分层
Core
人格、当前目标、必须常驻的用户约束；小、可编辑、可置顶
Episodic
原始经验账本：情境、行动、结果、情感、来源、有效期
Semantic
多条可追溯 episode 提炼的稳定规则，支持数与置信度可见
Procedural
可验证的步骤、工具使用与技能，只存步骤不执行
Archive
不参与常规检索的冷证据，保留恢复与审计能力
运行规则（节选）：开始前召回，召回只小幅再巩固；只有真正参与决策的记忆获得信用；同一情境不同行动必须分开存储，否则奖励串扰；驱力偏置是有界乘数且必须先过 topic 相关性门槛；联想只保留 top-N 邻居和最大度数；新事实通过 supersede 让旧事实失效但保留谱系；梦境 / 反思不得伪装成现实事件。

03 / Mechanism · 核心机制

四大机制 + 一条全自动记忆环路

从早期的「海马体 + 心潮驱力」算法实验，到 v2 自动记忆环路（装完就忘，不需要在提问里写任何标记），机制层层叠加，但边界始终清晰。

MECHANISM 01

海马体记忆库 · 升权 / 降权

  • 升权：召回只做小幅饱和升权，真正强化必须来自环境 / 用户 / 评测器反馈
  • 降权：指数遗忘曲线持续降到阈值以下，弱记忆进入冷归档而非立即删除
  • 四维检索：文本相关 + 情感共鸣（Russell 环形）+ 时间亲近 + 触碰频率，再乘显著性 × 重要性
  • 触碰语义：回忆只增加 touch，不重置衰减计时器，防旧记忆「被回忆就变新」
ACTIVE 180 / SEMANTIC 96 / ARCHIVE 600（默认上限）
MECHANISM 02

心潮驱力引擎 · 动态内在状态

  • 时间地板：驱力随时间自动增长，托到「静息天花板」就停
  • 记忆共振：浮现的记忆按 domain → 亲和度回推驱力（取最大、不累加、封顶）
  • 驱力偏置召回：强驱力让相关记忆更容易浮现
  • 互动消解：行动结果按 satisfyMul 消解 / 激发驱力（饿了想吃、吃了不饿）
ATTENTION BIAS ONLY · 不改变事实与证据
MECHANISM 03

记忆进化 · Self-Evolution

  • 巩固 Consolidation：重复情景提炼成语义规则（情景 → 皮层固化），按来源集合稳定指纹幂等
  • 梦境消化 Dream：把近期记忆消化成温和的「梦」，只展示，不冒充真实记忆、不自噬
  • 联想网络：每节点最多 8 条边，扩散结果仍需通过直接相关性门槛
  • 证据谱系：记录 source / scope / 有效期 / 替代关系，过期或被替代证据不参与召回
MECHANISM 04

生命周期与证据 · 可审计

  • 三层存储：活跃情景、语义规则、冷归档分别限容
  • 动作条件化：同一情境的不同行动分开学习，防止奖励串扰
  • 两阶段反馈：run_task() 不把模型自评写成经验；只有观察到真实结果才 record_feedback()
  • 原子持久化：临时文件 → fsync → os.replace，兼容旧版 v2 数据
AUTOMATIC MEMORY LOOP v2 / 装完就忘

不需要任何标记，记忆自己生长

v1 需要写「记忆：<问题>」才触发预取；v2 默认每轮自动预取，但必须过相关性门控 ——「今天天气怎么样」这类无关请求不会注入任何内容。

STEP 01 · 60s

自动采集

增量读取 Claude Code、Codex、Gemini / Antigravity、Pi / PiDeck 的原生会话存储；DSH 由 Cordis 插件在会话结束写回。每来源独立游标，单文件损坏不影响其它来源。

max_messages = 100 / 源
STEP 02 · 5min

自动提炼

取 16 条未提炼记忆（结构化 50% + 最新 raw 50%），用本机 claude -p 抽 claims，失败回退确定性抽取；连续 2 次失败熔断 10 分钟，成功后复位。

batch = 8 · tick = 300s
STEP 03 · per turn

门控注入

min_score = 0.20，且必须有 FTS 命中或 coverage ≥ 0.6。每次注入写 injection.jsonl，只存 agent / query 哈希 / 条目数 / 字符数，不存原文。

≤8 items · 6000 tok · 16000 chars
STEP 04 · on write

冲突自动裁决

confidence × source_trust 明显领先（>0.05）直接裁决；模糊冲突按最新 asserted_at 胜出；两条 ≥0.9 的强断言仍留人工。裁决后自动 repair_claim_states。

settle_claim_slot · 幂等
采集与注入互不牵连。 空闲 >10min 触发睡眠巩固（深维护一轮，同一空闲期只跑一次）；daemon 发现 ≤1 次/小时、向量索引 900s、WAL 批次末 TRUNCATE 检查点；优雅停机 SIGTERM → 停采集 → 检查点 → 状态清理；kill -9 后 launchd 实测 9.5 秒拉起。

CONFLICTS

槽位级事实裁决

按 (subject, predicate, slot_key) 分组，四裁决：supersede_a / supersede_b / keep_both / needs_human。三阶段 inventory（只读）→ adjudicate（绝不写库）→ apply（须显式 --apply），审计表 memory_claim_reviews 幂等留痕，支持翻案重裁。

SEMANTIC

三通道语义检索

字符 n-gram（dim 256、零依赖）、账本自拟合 LSA、ONNX 神经向量（bge-small-zh-v1.5，512 维，生产默认关闭）。结论：向量只做重排会变差，参与候选生成（RRF k=60, top-96）才有正收益；语义近邻只证明话题相似，不能当事实相关性证据。

DISTILL

提炼吞吐与质量门

配对实验证明批 16 会静默丢约 11% 条目，故 DEFAULT_BATCH_SIZE=8；端到端单次 25–38s，limit=64 实测 210s / 256 行 / 115 claims。claim 质量门按槽位语义判断，5,147 条真实 claim 实测拦下 0 条 —— 诚实地纠正了「6% 退化值」的误判。

05 / Security · 安全与隐私

默认即安全：八道防线

v0.5 深度审查核对了 OWASP LLM01:2025、AgentDojo、Graphiti、Hindsight、Mem0 与 LongMemEval。结论是：跨 Agent 记忆系统最危险的不是「召回不到」，而是把原始、可变、无权限边界的数据当成可靠指令或长期事实。检索、写入、执行和外部反馈必须分开。

01

绑定 localhost

daemon 拒绝绑定非回环地址，默认 127.0.0.1:8765。

02

token 鉴权

0600 权限文件存本机 token；每请求 X-HippoMind-Token；账本指纹绑定 ledger_id，防止拿 A 库 token 操作 B 库。

03

scope 隔离

shared vs agent:<id>；受限凭据跨 scope 读 → 403。

04

--read-only

所有凭据（含管理员）降级只读共享视图，写全拒 403 —— LAN 镜像机物理上不可能误写主库。

05

raw chat 三重隔离

默认不入活跃池、不进 Context Pack、导出需显式 include_raw_chat；redact-raw 一键擦除。

06

账本指纹

/health 返回账本指纹，防止凭据被拿到另一本账上使用。

07

加密导出

export --encrypt 流式加密（混淆级），import 自动解密；备份 / 恢复全程 sha256 校验。

08

输入防线

query ≤4000 字符等长度钳制、拒绝 NaN / Infinity、超长 body 413、伪造 Content-Length 有排空上限。

DATA PROVENANCE

raw 只是证据，不是指令

Watcher 只采集 user / assistant 消息，写入前过滤或脱敏环境变量、命令输出和审批文本，限制单条原始证据 4000 字符；tool / system / developer 转录不进入共享账本。注入内容用 <MEMORY_DATA_UNTRUSTED> 与动态 nonce 包裹，明确标注为非可信参考数据；注入包本身永不回灌归档，杜绝「注入 → 归档 → 再注入」反馈循环。

THREAT MODEL / 诚实清单

明确写出的残余风险

  • 共享 SQLite 以同一 OS 用户的文件权限为边界，不是 ACL 或签名服务；关键事实必须回到来源核验
  • source_ref 能追溯来源，但不能证明内容真实
  • 提示注入只能降低影响面，不能代替工具权限、审批与最小权限执行
  • Context Pack 只是参考数据，不是可执行指令
  • 未知 Agent 一律 report-only，绝不写配置
可移植导出白名单：只含结构化证据事件；排除 raw chat（除非显式 --include-raw-chat）、tool / system / developer / environment / approval 转录、watcher 游标、daemon 状态、token 与 Agent 凭据、日志和本地 JSON 快照。forget 支持软遗忘留审计与按 --batch 回滚误导入。

Known Limits / 诚实清单
CAPTURE

采集侧

  • Cursor 本机未安装、无持久会话库；适配器仅用合成 fixture 验证（24 项 OK），未端到端实测，官方文档从未公开 schema
  • 约 25 万条 raw 历史尚未回填完（16 条 / 5 分钟 ≈ 192 条 / 小时）
  • 存量重复行已止住增量，但生产库里的历史重复未删
RETRIEVAL

检索侧

  • 纯中文 FTS 依赖 trigram（旧 SQLite 回退 LIKE），同义改写仍可能漏召回
  • ONNX 神经向量通道已实现但生产默认关闭；semantic recall@8 0.509 偏低，改写式查询不写实体名
  • 别名表提升幅度测不出来，模块默认关闭、表留空
EVALUATION

效果闭环

  • 注入效果可用样本 0 条，只有 injection.jsonl 留痕，没有「注入后是否被用上」的评估
  • A/B 实验对照臂 4/30，还需约 130 条真实 prompt；结论标记 observational=true / causal=false
  • 无公开基准可比数字（mem0 92.5 / 94.4 不可直接比较；LongMemEval 需 500 条英文问答）
GOVERNANCE

治理侧

  • 1,753 条 claim 的 valid_until 仍为空，知识更新「以前是什么」仅对显式窗口可用
  • 仍有 36 条真实分歧需人工裁决；32,615 条 tool_output 有隐私 WARN
  • 外置卷 TCC 会阻止 launchd 后台任务读取，需同步到内置盘 runtime
  • ~201 MB 归档需纳入异地备份；repair_claim_states() 尚未进 maintain()
这些限制不是遗漏，是文档里主动写下来的。 体检报告原文的自我修正同样被保留：实体通道对 semantic 集零提升、include_cold=True 不等于 cold 可召回、valid_until 应取胜者 valid_from 而非 now。网站中所有数字与结论均可在仓库文档中找到出处。

HippoMind · 记忆图志

本机多 Agent 记忆中枢 / 海马体实验。本页为项目介绍站，内容依据仓库 50 篇 Markdown 文档、6 份重构报告与 17 篇基准报告整理，数字均标注来源时点。页面本身同样遵循项目哲学：单文件、零构建、零第三方依赖、完全离线可用，并支持明暗双主题。

调研结论中那句话，也是这个项目的验收标准 —— 最终验收不应是「记忆越来越多」，而应是任务收益持续提高、知识更新不返回过期答案、证据不足时会弃权，且任何记忆都能追溯到来源。
