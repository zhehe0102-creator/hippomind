# 对标报告 · 2026-08-24（迭代 27：检索延迟剖析轮）

## 本轮性质
cProfile 驱动的检索性能轮：在 69 万行生产账本副本（2.24GB，raw 聊天占 99%+）上
剖析 recall/context 全路径，落地 4 项优化，平均 Context Pack 构建 **923ms → 161ms
（5.7×）**，最差单查询 **11s → 539ms**。

## 落地优化（证据：本文末基准数字）
1. **trigram 短语救援替代全表 LIKE**（ledger.py search）：≥3 字符救援词走
   `memory_fts MATCH`（trigram 子串语义等价 LIKE '%t%'），索引路径 <10ms；
   并证明短语 MATCH 为空时同词表扫描不可能命中 → 直接跳过。
2. **LIKE/bigram/raw 三条兜底通道有界窗口化**：只在新度最高 N 行内扫描
   （100k/100k/20k），最坏成本有界；小库（<窗口）行为不变。
3. **schema v8 迁移**：`idx_memories_updated` + `idx_memories_structured_recent`
   （raw_chat=0 部分索引，结构化行仅占 1.5%）+ 迁移内 ANALYZE。
   关键发现：无统计信息时规划器选 idx_memories_scope 全扫（0.8-6s），
   ANALYZE 后改选部分索引（34ms）。
4. **短语救援排序改 bm25**：`ORDER BY updated_at` 会诱导规划器沿 updated_at
   索引全表游走（77 万行 ≈1s）喂排序；bm25 序留在 FTS 空间内。

## 联网对标（≥2 仓库）

### Zep / Graphiti（getzep/graphiti；论文 arXiv:2501.13956）
- 链接：https://github.com/getzep/graphiti 、https://arxiv.org/abs/2501.13956 、
  https://www.getzep.com/ai-agents/temporal-knowledge-graph/
- 机制：双时态知识图谱（valid_from/valid_to + observed/recorded 四时间戳）、
  事实失效不删除、episode 级溯源；检索 = 余弦语义 + BM25 + 图 BFS 三路混合，
  官方目标 **sub-200ms p95**（Context Graph Engine 托管版）。
- 对比：HippoMind 已有双时态字段（v4 迁移 valid_from/valid_until）与
  FTS+LIKE+RRF 混合检索；本轮后平均 161ms 已进入 Zep 宣称的同一延迟档。
- 差距/可借鉴：
  - **as-of 点查 API**：Zep 支持"该日期时为真"的历史切片查询；HippoMind 有
    时间窗过滤（上周/昨天解析）但无显式 as_of 参数 → 列入 BACKLOG（P2）。
  - 图 BFS 通道：HippoMind 有实体邻域图层但检索主链路无图遍历通道 → 观察项。

### Mem0 v3（mem0ai/mem0）
- 链接：https://github.com/mem0ai/mem0 、
  https://docs.mem0.ai/platform/features/graph-memory 、
  https://mem0.ai/blog/memory-retrieval-strategies-for-ai-agents 、
  https://github.com/mem0ai/mem0/pull/5377
- 机制：语义 + BM25 + 实体匹配三信号并行评分融合；**BM25 只做加权不做召回
  扩展**（与 HippoMind 的多通道 RRF 召回相反——我们让每个通道都贡献候选，
  由 coverage/可靠性门兜底，对 CJK 长尾更稳）；混合检索典型延迟
  **~100-150ms**，rerank +150-200ms；LoCoMo 71.4→91.6、LongMemEval 67.8→93.4。
- 可借鉴（已列入 BACKLOG）：
  - **慢查询哨兵**：mem0 设 2s 慢查询阈值并触发 notice；HippoMind daemon 可
    在 /stats 暴露 search_p95 与慢查询计数（P3，下轮可做）。
  - **实体增强批并行**（PR #5377）：批量 embed + 并行实体检索 5× 提速；
    HippoMind embedder 通道候选 >600 时直接跳过，暂无此瓶颈 → 观察。

### 结论
本轮 4 项优化均为剖析驱动的实证修复，无对标项可直接照搬；新吸收 backlog：
as_of 历史切片查询（P2）、search 慢查询哨兵与 p95 指标（P3）。
