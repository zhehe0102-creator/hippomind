# 对比报告 · 2026-08-21（本轮：英文评测 / 指南增补 / 并发基准）

## 参照系统（≥2 外部仓库）

1. **mem0ai/mem0** — https://github.com/mem0ai/mem0
   LLM 抽取式记忆层：add() 走 LLM 事实抽取→向量库+图存储双写；检索纯语义
   （embedding top-k）。冲突处理靠 LLM 在写入时决定 ADD/UPDATE/DELETE。
2. **getzep/zep** — https://github.com/getzep/zep（社区版）/ Graphiti 引擎
   时序知识图谱：事实带 valid_at/invalid_at 双时间戳，bi-temporal 检索；
   社区版依赖 Neo4j。冲突=新事实使旧事实 invalid_at 生效（不删除）。
3. **letta-ai/letta**（原 MemGPT）— https://github.com/letta-ai/letta
   分页式上下文管理：core memory（in-context）+ archival/recall（外存），
   agent 自主调用工具换页；无跨 Agent 共享层。

## 差距与借鉴点（诚实记录）

- **zep 的 bi-temporal**：valid_at/invalid_at 与我们 claim supersede 谱系等价，
  但其「时间点重建历史视图」API（as_of 查询）我们没有——时间轴回放是 GUI 层
  近似，缺 API 级 as_of。→ 已入候选池评估。
- **mem0 的图记忆**：实体关系图查询（多跳）我们靠 commons 层共现边近似，
  无显式关系类型。当前场景（个人助理记忆）收益存疑，暂不跟进。
- **letta 的 self-editing memory**：agent 自主改写 core memory 区——我们的
  state 层由系统管理，agent 只读。保持现状：可控性优先。
- **结论**：本轮「暂无可直接落地的改进项」维持；下一轮对标重点转向
  as_of 历史视图 API 可行性。
